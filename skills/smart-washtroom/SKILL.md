## 前置条件
- 查询脚本已集成 `SmartSSOSession`，认证由脚本内部自动处理，无需人工干预
- 目标站点：`https://xz.corp.kuaishou.com/is-intelligent-device`

## 强约束（必须遵守）
1. **凡是轮询任务，必须使用 `crontab` 实现**，禁止手工循环刷新、阻塞等待或伪轮询。
2. 用户未指定轮询参数时，默认 **3 分钟/次，最多 20 次**。
3. 轮询任务在「开始」「命中空闲」「异常/超时结束」三个节点，都要通过 KIM 通知本人（当前用户名/邮箱前缀）。
4. **认证由脚本内部自动处理**，AI 不得要求用户手动提供手机号、验证码或 Cookie；若脚本返回认证错误，直接原文提示用户，禁止自行构造登录流程。
5. **园区名称和楼宇名称必须来自 `--list-gardens` 接口返回的实际数据**，禁止 AI 自行猜测或补充未经确认的园区/楼宇名称。

## ⚠️ 容易遗漏的点
- **必须先核对楼宇**：用户指定2号楼时，若页面当前是3号楼，直接查询会返回错误结果
- **楼宇切换必须用 API**：不要尝试在页面上点击切换，直接调接口更快更稳

## 主流程（单次查询）

### 步骤 1：执行查询

直接调用 `query_wc.py` 执行查询，认证由脚本内部自动处理，无需人工干预：

**查询命令示例：**

```bash
# 查询指定园区和楼层
uv run --refresh-package ks_aimate <skill_directory>/scripts/query_wc.py --garden "万家灯火" --floor 8

# 查询指定园区、楼宇和楼层
uv run --refresh-package ks_aimate <skill_directory>/scripts/query_wc.py --garden "元中心" --building "1号楼" --floor 3

# 列出所有可用园区和楼宇
uv run --refresh-package ks_aimate <skill_directory>/scripts/query_wc.py --list-gardens

# 查询默认园区（不指定园区时使用第一个可用园区）
uv run --refresh-package ks_aimate <skill_directory>/scripts/query_wc.py --floor 8
```

### 查询结果

脚本会：
- 调用快手智能卫生间 API 获取实时数据
- 根据用户指定的园区/楼宇/楼层筛选结果
- 显示每个卫生间的空闲率和坑位状态（空闲/占用及占用时长）

> **提示**：若记忆中没有用户工位楼层，询问并记忆，便于后续就近推荐

### 参数说明

| 参数 | 简写 | 说明 | 示例 |
|------|------|------|------|
| `--garden` | `-g` | 园区关键词 | "万家灯火"、"元中心"、"五彩城" |
| `--building` | `-b` | 楼宇关键词 | "1号楼"、"B座" |
| `--floor` | `-f` | 楼层号 | 8、3、12 |
| `--list-gardens` | - | 列出所有可用园区 | - |

## 轮询任务（必须使用 crontab）
### 触发条件
- 用户表达持续监控诉求，例如「帮我盯着」「有空位通知我」「每隔几分钟查一次」。

### 执行步骤
1. 先做一次即时查询，确认查询范围（园区、楼宇、楼层、卫生间范围）。
2. 创建 `crontab` 轮询任务（不要用普通循环模拟）：
   - `interval`：用户指定优先；未指定用 3 分钟。
   - `maxRuns`：用户指定优先；未指定用 20 次。
   - `stopCondition`：出现满足条件的空闲便器。
3. 轮询启动前发送 KIM 通知本人：已开始轮询、间隔和最大次数。
4. 每轮由 `crontab` 执行查询逻辑（必要时先刷新页面，再读取状态）。
5. 命中空闲后立即发送 KIM 通知并停止任务。
6. 达到最大次数、异常中断或超时后，发送 KIM 通知并结束任务。

### 通知模板
- 开始：`已开始轮询：{楼宇/楼层}，间隔 {interval}，最多 {maxRuns} 次。`
- 命中：`发现空闲便器：{位置/编号}，已停止轮询。`
- 结束：`轮询结束：未命中空闲（或任务异常：{error}）。`

## 备注
- 时间解释：页面上的占用时长（如 `< 10min`）表示当前占用尚短，不代表会立刻空闲。
