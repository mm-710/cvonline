# 会议室预订 Skill 优化记录

## 优化日期
2026-04-17

## 问题来源
用户反馈：在实际使用中，AI 会编造不存在的会议室信息，例如：
- "北京-元中心T1 2层-209 柳浪" — 该会议室不存在
- "北京-元中心T1 3层-306 松涛" — 实际叫"太阿"，不是"松涛"
- "北京-元中心T1 3层-307 霜林" — 实际叫"毫曹"，不是"霜林"

## 根本原因分析
1. **输出截断**：当会议室数量较多时（如查询 T1 有 385 间），终端输出被截断（出现 `...`），AI 看不到完整数据
2. **信息过载**：几十个会议室同时输出，AI 难以准确记忆和引用
3. **缺少约束**：文档中没有明确禁止 AI 编造信息的约束条款
4. **缺少定位**：无法根据用户位置智能排序，推荐不够精准

## 实施的优化

### 1. 增加强制约束条款 ✅
**位置**：SKILL.md 顶部

添加了醒目的 `【强制约束】数据准确性要求` 部分：
- 明确要求"所有答复都必须从脚本输出或接口返回中找到准确的数据来源，严禁推测、编造、臆想"
- 列举了具体的违规示例（真实案例）
- 给出了正确做法

### 2. 脚本功能增强 ✅

#### 2.1 智能位置排序
```python
def rooms(..., user_location: Optional[str] = None, ...):
```
- 新增 `--user-location` 参数（如 "T1-2层"）
- 自动优先显示：同楼栋同楼层 → 同楼栋邻层 → 同楼栋其他层 → 其他楼栋
- 解决了"优先在我的办公楼层"的需求

#### 2.2 输出数量控制
```python
def rooms(..., limit: Optional[int] = None, ...):
```
- 新增 `--limit` 参数，限制显示数量
- 避免输出过多导致截断
- 显示提示信息：还有多少间未显示

#### 2.3 JSON 格式输出
```python
def rooms(..., json_output: bool = False, ...):
```
- 新增 `--json` 参数
- 输出结构化数据：total、displayed、time_range、rooms 列表
- 便于 AI 精确解析，避免幻觉

#### 2.4 增强 my-events 输出
- 同时显示 `eventId` 和 `calendarId`
- 取消预约时不需要重新查询

#### 3.3 新增常见陷阱部分

## 效果验证

### 测试 1：智能排序
```bash
uv run ... rooms --from-time "2026-04-17 18:00" --to-time "2026-04-17 19:00" \
  --building "北京-元中心T1" --user-location "T1-2层" --limit 5
```

**结果**：
- 总共 385 间空闲会议室
- 优先显示的前 5 间**全部在 T1 2层**
- 完美匹配用户位置需求

### 测试 2：JSON 输出
```bash
uv run ... rooms --from-time "..." --to-time "..." --json --limit 3
```

**结果**：
- 输出结构化 JSON 数据
- 包含 total、displayed、time_range、rooms
- 每个会议室包含完整的 building、shortName、capacity、floor、device、meetingRoomId

## 预期效果

### 问题解决
1. ✅ **不再编造会议室名称**：通过强制约束和输出控制，AI 只能使用脚本返回的真实数据
2. ✅ **不再输出截断**：通过 `--limit` 参数，控制输出数量在合理范围内
3. ✅ **推荐更精准**：通过 `--user-location` 参数，优先显示用户附近的会议室
4. ✅ **取消更便捷**：my-events 同时输出 eventId 和 calendarId

### 推荐使用模式
未来当用户说"查会议室"时：
1. 如果用户提到位置（如"我在 T1-2层"），使用 `--user-location`
2. 默认使用 `--limit 10`，避免输出过多
3. 如果需要程序化处理，使用 `--json` 格式
