# Skill 市场判重（内联自 market-deduper）

在开始编写新 Skill 前，先判断市场里是否已存在高度相似的能力，避免重复建设。

## 工作流

```
Step 1 → 检索市场 → Step 2 → 语义重排筛选 → Step 3 → 展示并让用户判断
         ↓ 有匹配候选                              ↓ 用户说"是，直接用" → 结束，提供链接
                                                  ↓ 用户说"不是，要新建" → Step 4 → 采集反例
         ↓ 无匹配 → 直接进入创建流程，跳过 Step 3/4
```

---

## Step 1：检索市场

提炼用户意图，运行脚本：

```bash
uv run <skill_directory>/scripts/search_market_skills.py --query "<用户意图描述>"
```

脚本返回最多 15 条关键词粗排候选（`candidates`），不是最终结果。

---

## Step 2：AI 语义重排 + 筛选

脚本只做关键词粗排，语义理解由 AI 完成：

- 读取 `candidates` 列表，结合 `query` 字段
- 过滤掉名字相关但功能不符的候选（如"不负责会议室预约"的理发店 Skill）
- 按语义相关度排序，取最多 3 条高相关候选

---

## Step 3：展示链接，让用户判断

**必须附上可点击链接**，由用户自己判断：

```
市场中发现以下相似 Skill，请确认是否满足您的需求：

1. **<slug>**
   链接：https://myflicker.corp.kuaishou.com/flicker/skills/<slug>
   描述：<summary 前 150 字>

👉 A. 是，我直接用这个  B. 不是，需要新建
```

不替用户做判断。**若无相似候选**，直接告知并进入创建流程。

---

## Step 4：用户选"新建"时——采集触发反例

脑暴 5-8 个用户可能说出的 prompt，让用户确认哪些应触发新 Skill、哪些不该：

```
✅ 应该触发（新 Skill 负责的）：
  1. "..."
  2. "..."

❌ 不应该触发（已有 Skill 或其他工具负责的）：
  3. "..."（→ 建议用 <相似slug>）
```

确认后将反例整理进新 Skill 的 description「不唤醒」部分。

---

## 注意事项

- 若用户说"我已经知道没有相似 Skill 了，直接帮我创建"，跳过本流程
- 判重是前置步骤，不负责 Skill 发布或安装
- 脚本路径使用 `<skill_directory>` 占位符
