## 智能楼层匹配逻辑

**匹配策略**：
1. 提取用户描述中的**关键字**（数字、字母、区域标识等）
2. 在 `get_enums` 返回的楼层列表中搜索匹配项
3. **优先精确匹配**：楼层数字必须完全匹配（用户说"3层"或"3F"，楼层名必须包含"3F"或"3层"）
4. 如果有多个匹配，列出候选项让用户选择
5. 如果搜索不到，提示用户确认楼层

### 示例 1：简单数字格式（元中心）

用户输入：`元中心 T1-2层`

```
1. 提取关键字：T1 + 2
2. 调用 get_enums，搜索包含 "1号楼" 和 "2层" 的结果
3. 找到：楼层 [327] 2层（在1号楼下）
4. 匹配成功：floorId=327
```

### 示例 2：复杂区域格式（万家灯火）

用户输入：`万家灯火 B区8层` 或 `8B` 或 `万家灯火8层B区`

```
1. 提取关键字：B + 8
2. 调用 get_enums，搜索包含 "B" 和 "8" 的楼层
3. 找到：楼层 [315] 8FB区
4. 匹配成功：floorId=315
```

### 示例 3：工位号格式（C5-191）

用户输入：`C5-191` 或 `万家灯火 C5-191`

```
1. 提取关键字：C + 5
2. 调用 get_enums，搜索包含 "C" 和 "5" 的楼层
3. 找到：楼层 [309] 5FC区
4. 匹配成功：floorId=309
```

## 关键原则（禁止违反）

1. **禁止使用默认园区/楼栋**：即使用户历史在元中心，也不得在用户未明确说园区时自动使用元中心
2. **禁止硬编码楼层映射**：除高频场景外，必须通过 `get_enums` 动态查询
3. **禁止猜测 floorId**：当枚举结果中有多个匹配时（如 T1-2层 vs T2-2层），必须向用户确认
4. **不确定必须确认**：当园区/楼栋/楼层无法从已知枚举匹配时，必须运行 `get_enums` 或向用户确认

**关键优化**：当会话中已执行过 `get_enums` 且结果在上下文中时，可直接使用已有结果，无需重复调用。但如果用户提到的园区/楼栋不在已有结果中，必须重新调用。
