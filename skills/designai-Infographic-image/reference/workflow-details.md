# 详细工作流程（Detailed Workflow）

> 本文档是 SKILL.md 的详细补充，包含完整的提示词生成规则和质量检查流程。

---

## 阶段3：双路线提示词生成详解

### 🅰️ 路线A：叙事流（不指定风格）

像 RAW 一样写——短、直接、连续叙述。不拆区块、不指定图表类型、不写风格词。

**提示词模板**：
```
生成一张{宽高比}的信息图，主题为"{主题}"。

{将原始内容改写为连续叙述段落。要求：
  - 保留所有数字、比例、年份等精确数据
  - 保留说明文字和括号备注（如「减脂与提神的首选」）
  - 去除所有 markdown 符号（**粗体**、|表格|、---分隔线、##标题符号）
  - 不加区块标题、不加编号前缀
  - 信息之间用句号或逗号自然连接
  - 控制总信息点 ≤ 8个，超出时合并或删减
  - 所有文字必须为中文
  - 段落末尾自然收尾，用一句 8-20 字的情感金句作为结束语，直接融入正文，不加任何标签前缀}

禁止元素——严格执行：
- 所有文字必须为中文，禁止将任何中文标签翻译为英文
- 禁止出现 9:16、16:9 等宽高比数字标注
- 禁止出现【】《》等格式符号装饰标题
- 禁止出现无说明文字的孤立数字刻度（0、2000 等）
- 禁止出现「区块」「面板」「主角区」等结构描述词
- 禁止出现 px/pt 等技术单位标注
- 禁止文字截断或重叠
- 禁止出现←箭头（时间方向必须朝右→）
```

---

### 🅱️ 路线B：风格矩阵引导

与路线A使用**完全相同的内容叙述段落**，但在开头追加一句**视觉风格引导句**。

**步骤1：匹配风格**

根据内容的「领域」和「基调」从风格矩阵中选择一个风格。

**步骤2：生成路线B提示词**

```
生成一张{宽高比}的信息图，主题为"{主题}"。

视觉风格：{从风格矩阵获取的风格描述句，1-2句话描述整体色彩和氛围}

{与路线A完全相同的内容叙述段落（含末尾金句，已融入正文）}

禁止元素——严格执行：
{与路线A相同的禁止元素列表}
- 禁止出现风格名称词汇作为图片中的可见文字
```

**风格引导句写法规范**：
- ✅ 用氛围/色彩/质感描述：「深色背景带蓝紫渐变光效，卡片有半透明玻璃质感，数字带霓虹发光」
- ✅ 用情绪词：「温暖的咖啡色调」「冷峻的科技感」「明亮清新的扁平风格」
- ❌ 不写风格ID：不写 `gradient-tech`、`soft-gradient` 等标签名
- ❌ 不写精确hex色值：不写 `#0A0A0F`、`#4F46E5`
- ❌ 不写布局指令：不写「三列卡片」「顶部大字」等结构

### 提示词反检查清单

| 检查项 | 标准 | 违反时修复 |
|-------|------|----------|
| **有没有区块标题** | ❌ 不允许。如出现「XX作用机制：」「XX数据：」等命名段落 | 删除标题，将内容融入连续叙述 |
| **有没有图表类型指令** | ❌ 不允许。如出现「横向条形图」「4阶段卡片」「竖向时间轴」 | 删除，让模型自主选择 |
| **有没有风格名称或hex颜色** | ❌ 不允许。如出现 `gradient-tech`、`#1A1655` | 删除 |
| **有没有布局权重指令** | ❌ 不允许。如出现「顶部三列大字」「核心数字区」「占40%」 | 删除 |
| **内容是否连续叙述** | ✅ 必须。像一段话一样自然流动 | 合并碎片段落 |
| **禁止元素是否包含防泄漏三件套** | ✅ 必须 | 补全 |
| **底部金句是否融入正文末尾** | ✅ 必须（作为正文最后一句，不加标签前缀） | 补充并移除标签 |
| **是否全中文** | ✅ 必须 | 翻译英文内容 |

## 阶段4：双路线并行生图

同时调用脚本生成两张图：

```bash
# 路线A：叙事流
uv run "<skill_directory>/scripts/generate_image.py" \
    --prompt-file "output/{主题关键词}/route-A-prompt.md" \
    --output "output/{主题关键词}/route-A.jpg" \
    --resolution 2K \
    --aspect-ratio {宽高比} \
    --creator "{username}"

# 路线B：风格矩阵引导
uv run "<skill_directory>/scripts/generate_image.py" \
    --prompt-file "output/{主题关键词}/route-B-prompt.md" \
    --output "output/{主题关键词}/route-B.jpg" \
    --resolution 2K \
    --aspect-ratio {宽高比} \
    --creator "{username}"
```

> **两个脚本应并行调用**（先启动路线A为后台任务，再启动路线B），减少等待时间。

## 阶段5：自动质量检查（上限 3 次迭代）

对两张图分别检查，发现 P0 问题时修改提示词重新生成，**每条路线最多迭代 3 次**。

两张图都生成后，使用 `read_file` 逐一读取检查：

### P0 — 必须通过（任一失败则修改提示词重新生成该路线）
- [ ] 图片中是否出现结构描述词？（「主角区」「区块」「面板」等）
- [ ] 是否出现 px/pt 等技术单位标注？
- [ ] 是否出现格式符号【】《》作为标题装饰？
- [ ] 是否出现宽高比数字（9:16 等）或孤立刻度数字？
- [ ] 品牌/名称是否准确？
- [ ] **是否出现英文文字？**（中文内容图片中不应有英文标签）
- [ ] 是否出现风格名称词汇作为可见文字？（路线B特有检查）

### P1 — 强烈建议通过
- [ ] 所有关键数据是否正确显示？
- [ ] 文字是否清晰可读，无截断无重叠？
- [ ] 是否有明确的视觉主次节奏？
- [ ] 底部金句是否可见？

### 迭代规则

- **P0 有失败项**：修改该路线的提示词，重新生成，最多迭代 3 次
- **P0 全部通过**：该路线交付，无需继续迭代
- **第 3 次仍有 P0 问题**：标记问题，交付最终版本，不再迭代
- **每次迭代**：注明「迭代原因：{具体问题}」

### 最终交付

向用户展示两张图的结果，简要对比差异（视觉风格、数据呈现、氛围感），让用户选择偏好的版本。

## 阶段6：后续编辑引导

交付完成后，**固定展示以下引导提示**：

```
✅ 生成完成！

💡 还可以继续优化：
• 输入「换风格 + 编号」对选定版本进行风格迁移
  例如：「换风格 10」= 将选中的图改成科技暗黑风
• 直接上传图片并描述修改需求，进行局部调整
  例如：上传图片 + 「把背景改成深色调」
• 上传一张参考图，我可以按该图的视觉风格重新生成
  例如：上传参考图 + 「按这个风格给我做信息图」
```

> ⚠️ **「换风格 + 编号」触发图生图**：以用户选定的那张图为参考图，构造风格迁移提示词，调用图生图接口生成。

## 【图生图模式】阶段E：图片编辑详解

### 触发条件

| 触发方式 | 说明 |
|---------|------|
| 用户上传图片 + 描述修改 | 对上传图片进行局部调整或风格改变 |
| 输入「换风格 + 编号」 | 对最近生成的图片进行风格迁移 |
| 上传参考图 + 新内容 | 按参考图风格生成全新信息图 |

### 执行步骤

**Step 1：读取图片**

使用 `read_file` 读取图片文件，获取原始字节数据。

**Step 2：构造编辑提示词**

根据用户需求类型构造不同的提示词：

- **风格迁移**（「换风格 10」）：
  ```
  保留图中所有内容、数据和文字的准确性，将整体视觉风格改为{目标风格描述}。
  禁止修改图中任何数字、百分比、文字内容。禁止出现英文标签。
  ```

- **局部调整**（「把背景改成深色」）：
  ```
  {用户的具体修改描述}。保持图中其他元素不变，只调整{具体部分}。
  禁止出现英文标签。禁止修改未被提及的内容。
  ```

- **参考图生图**（上传参考图 + 新内容）：
  ```
  参考输入图片的整体视觉风格、色调和排版感，生成一张全新的信息图，主题为"{新主题}"。
  {新内容的叙事流段落（按文生图模式规则整理）}
  禁止元素：{与文生图模式相同的禁止元素列表}
  ```

**Step 3：调用图生图脚本**

```bash
uv run "<skill_directory>/scripts/generate_image.py" \
    --prompt "..." \
    --image-file "path/to/input.jpg" \
    --output "output/{主题关键词}/edited.jpg" \
    --creator "{username}"
```

> 注意：图生图模式使用 `autoSize=true`，服务端自动决定输出尺寸，**无需指定宽高比和分辨率参数**。

**Step 4：展示结果并提供继续编辑选项**

展示编辑结果后，再次显示阶段6的「后续编辑引导」，让用户可以继续迭代。

## 多图生成场景

当内容量过大（超过20个核心要点）或用户明确要求系列图时，自动拆分为多张图：
- 每张图对应一个子主题，保持内容聚焦
- 顺序命名：`output/{主题}-01.jpg`, `output/{主题}-02.jpg`...
